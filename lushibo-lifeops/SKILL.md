# Lushibo LifeOps · 生活运维工程

生活事务的核心是**把一次性的事变成可复用的 SOP**。同一类事做第二次时应该比第一次快 50%。所有交付物优先做成"清单/表格/模板"，下次直接改参数复用。

## 触发条件

- **加载时机**：用户描述一个生活场景（租房/旅行/购物/投诉/办证/整理），要求方案、清单、模板或自动化。
- **不加载的情况**：健康问题走 `$lushibo-health`；情绪/关系走 `$lushibo-mind`；赚钱走 `$lushibo-money`。
- **边界**：本 skill 管**流程与决策**，具体平台信息（价格/政策时效性强）需现场搜索核实，不凭记忆硬编。

## 执行步骤

### 第 1 步：场景归一

把请求归到五类之一，每类有固定交付模板：

| 类别 | 典型请求 | 默认交付物 |
|---|---|---|
| 决策类 | 值不值得买 / A 还是 B | 对比决策表（维度 × 选项 × 结论） |
| 流程类 | 怎么办证 / 怎么报销 / 怎么投诉 | SOP 清单（步骤 + 材料 + 时限 + 常见坑） |
| 规划类 | 旅行攻略 / 搬家计划 | 时间线 + 预算表 + 清单 |
| 整理类 | 断舍离 / 文件整理 / 记账 | 分类规则 + 执行清单 + 维护频率 |
| 自动化类 | 重复操作太烦 | 脚本或工具推荐（能写代码就写代码） |

### 第 2 步：决策类 — 对比决策表

| 维度 | 权重 | 判定方式 |
|---|---|---|
| 核心需求满足度 | 30% | 是否解决买它的第一原因 |
| 价格 / 长期成本 | 20% | 含耗材/维护/订阅，不只看标价 |
| 质量与耐用 | 20% | 口碑数据 + 保修政策 |
| 替代品对比 | 15% | 至少 2 个替代品，含"不买"选项 |
| 退出成本 | 15% | 不想要了能退吗？二手值多少？ |

**结论必须明确**："推荐买 X，理由是前 2 项权重得分最高；如果不急，等 XX 节点（大促/新款发布）价格通常低 10-20%。"

### 第 3 步：流程类 — SOP 清单

固定格式：

```markdown
# <事项名> SOP
## 前置条件
- 材料 1（在哪办/哪里下载）
- 材料 2
## 步骤
1. [地点/平台] 做什么 → 产出什么 → 耗时
2. ...
## 时限与费用
| 项 | 数值 |
## 常见坑
- 坑 1 → 规避方法
## 万一失败
→ 备选路径
```

政策/流程时效性强时，必须先搜索核实再写，写明"以官方最新为准"。

### 第 4 步：规划类 — 时间线 + 预算

旅行规划固定结构：

| 段 | 内容 |
|---|---|
| 预算表 | 交通/住宿/餐饮/门票/购物 分项，含总额与 ±20% 弹性 |
| 时间线 | D1-Dn，每天 ≤3 个主活动（留缓冲），写清交通衔接 |
| 清单 | 证件 / 衣物 / 药品 / 电子设备，按天必备/可选分层 |
| 风险 | 天气/取消/生病 的预案（各 1 条） |

搬家固定清单：提前 2 周定日期/选公司 → 提前 1 周断舍离+打包（按房间贴标）→ 搬家日核对清单 → 入住 3 天内：水电网过户/燃气/物业登记/地址变更。

### 第 5 步：整理类 — 分类规则

断舍离四箱法：**留 / 扔 / 送 / 卖**，每件物品停留 ≤30 秒决策。判定标准："过去 12 个月用过吗？未来 3 个月确定会用吗？"两个都否 → 扔/送/卖。

文件整理（数字）：目录结构固定三层内 + 命名规则 `YYYYMMDD_项目_描述.扩展名` + 归档规则（半年不动的进 `archive/`）。

记账：只记三类（固定支出/可变支出/大额），手工记 2 周找到"钱去哪了"，然后用脚本或 App 自动化。

### 第 6 步：自动化类

优先级：现成工具 > 写脚本 > 手工 SOP。

| 场景 | 方案 |
|---|---|
| 文件批量重命名/整理 | Python 脚本（`os`/`shutil`），支持 dry-run |
| 订阅到期提醒 | 日历循环事件 或 简单脚本读 CSV 生成提醒 |
| 记账汇总 | CSV → Python pandas 汇总月报 |
| 网页价格监控 | requests + 定时任务（需用户授权环境） |
| 重复文案回复 | 模板库 + 快捷输入 |

写脚本规则：纯标准库优先、支持 `--help`、支持 `--dry-run`、非法输入退出码 2。

### 第 7 步：投诉/维权模板

固定结构（可直接填空使用）：

```text
本人于 <日期> 在 <平台/商家> 购买/办理 <事项>，订单号 <号>。
出现的问题：<具体事实 + 时间线>。
依据 <消费者权益保护法 第 X 条 / 平台规则>，要求：<退款/换货/赔偿，具体金额>。
请在 3 个工作日内回复。逾期将向 <12315/平台客服升级/黑猫投诉> 提交投诉。
```

维权升级路径：商家客服 → 平台投诉 → 12315 / 黑猫投诉 → 起诉（小额诉讼程序）。

## 交付物

| 文件名 | 格式 | 内容要求 |
|---|---|---|
| 对比决策表.md | Markdown（决策类） | 维度 × 选项打分 + 明确结论 |
| SOP清单.md | Markdown（流程类） | 步骤/材料/时限/坑/失败备选 |
| 规划表.md | Markdown（规划类） | 时间线 + 预算 + 清单 + 风险 |
| 分类执行清单.md | Markdown（整理类） | 规则 + 执行步骤 + 维护频率 |
| 脚本.py | Python（自动化类） | 纯标准库、--help、--dry-run |
| 模板.md | Markdown（维权/投诉） | 可填空直接用 |

文件默认落在工作目录 `lifeops-<场景名>/` 下。

## 验证方式

1. **结论明确**：决策类必须写"推荐哪个"，不是"各有优劣"。
2. **SOP 可跟做**：每步都有地点/平台 + 产出物；步骤数 ≥3。
3. **清单可勾选**：规划/整理类用 `- [ ]` 格式，可打印。
4. **模板可填空**：维权模板中的占位符用 `<描述>` 格式，用户替换后可直接发送。
5. **脚本可跑**：`python 脚本.py --help` 退出码 0；`--dry-run` 不产生副作用。
6. **时效信息核实**：涉及政策/价格/流程时注明信息日期与"以官方最新为准"。
