# Lushibo Botnet · C2 运维工程

C2 工程的评价标准只有三个：**上线率、存活时长、被发现的代价**。所有设计都在"隐蔽性 ↔ 稳定性 ↔ 运维效率"之间取舍，必须明确写下每个取舍的代价。

## 触发条件

- **加载时机**：用户要设计 C2 架构、提升上线率与存活时长、做权限维持、批量管理大量被控端、分析回连异常、设计检测对抗方案。
- **中文关键词**：肉鸡、远控、控制端、C2、上线、保活、心跳、睡眠、权限维持、持久化、批量管理、分组、任务下发、重定向、域前置、载荷投递、会话管理、检测对抗、掉线。
- **英文关键词**：C2、implant、beacon、listener、redirector、jitter、sleep、keep-alive、persistence、fleet、tasking、malleable profile、domain fronting、egress、failover。
- **不加载的情况**：**样本本体**的逆向与家族归属走 `$lushibo-malware`；**内存结构/注入实现细节**走 `$lushibo-memory`；**免杀与 hook 绕过实现**走 `$lushibo-evasion`；**检测与响应侧**走 `$lushibo-bluesec`。
- **边界**：本 skill 管**控制面与运维面**（架构、保活、维持、批量、链路），不管载荷免杀实现（归 evasion）。

## 执行步骤

### 第 1 步：定义运维指标

先写清四个数字，再选架构：

| 指标 | 定义 | 目标示例 |
|---|---|---|
| 上线率 | 成功建立会话数 ÷ 投递数 | ≥60% |
| 平均存活时长 | 会话从上线到失效的中位时长 | ≥72 小时 |
| 心跳可观测性 | 单位时间内产生的可关联事件数 | 越低越好 |
| 任务下发延迟 | 下发到执行的时间 | ≤2 个心跳周期 |

判断标准：上线率低是投递问题，存活短是检测问题，延迟高是架构问题。三者不要混着调。

### 第 2 步：C2 架构设计

四层结构，逐层定职责：

| 层 | 职责 | 关键设计 |
|---|---|---|
| 投递层 | 把植入体送到目标并触发 | 与 C2 地址解耦，地址可后置下发 |
| 通信层 | 会话建立与数据往返 | 多通道冗余（主/备/应急），协议可切换 |
| 控制层 | 任务队列、结果回收、会话状态 | 无状态前端 + 有状态后端，便于横向扩展 |
| 运维层 | 分组、批量任务、版本管理 | 所有操作可审计、可回滚 |

拓扑建议（按规模）：

- 单机测试：植入体 → 监听端。
- 小规模（<100）：植入体 → 重定向层 → 监听端，重定向层负责地址隐藏与协议转换。
- 中大规模（>1000）：植入体 → 多入口重定向池 → 消息队列 → 多监听端 → 统一控制台；入口与出口分离，任一层可独立替换。

硬规则：

1. **入口地址绝不出现在植入体里**（或用可轮换的引导地址），否则封一个死一片。
2. **每个通道要有独立的心跳节奏**，避免多通道同时回连形成固定周期。
3. **控制层必须能无状态重建**，会话状态持久化到存储，前端可随时替换。
4. 任务队列要有幂等 ID，重放不产生重复执行。

### 第 3 步：上线机制

上线成功率由四件事决定：可达性、触发时机、失败重试、环境适配。

| 环节 | 做法 | 常见失败原因 |
|---|---|---|
| 地址获取 | 引导地址池 + 备用域名 + 硬编码兜底 | 单一地址被封 |
| 触发 | 用户态触发、服务启动触发、登录触发 | 触发条件不满足 |
| 重试 | 指数退避（1s→2s→4s…上限 10 分钟）+ 随机抖动 | 固定间隔被识别 |
| 适配 | 检测代理设置、检测出网端口、回退 80/443/53 | 只走 443 导致不可达 |
| 校验 | 上线后先做一次最小能力自检（权限、出网、可用工具） | 上线即失败无反馈 |

自检项清单：当前用户与权限级别、是否管理员/root、出网方式（直连/代理）、可用解释器（PowerShell/python/bash）、系统架构、杀软与 EDR 存在性、时间同步状态。自检结果决定后续下发什么任务。

### 第 4 步：保活机制

| 机制 | 参数建议 | 代价 |
|---|---|---|
| 心跳 | 基础 60 秒 + 抖动 30% | 越短越容易被行为分析发现 |
| 睡眠/唤醒 | 睡眠期不产生任何网络行为 | 任务延迟上升 |
| 多通道 | 主 TCP + 备 HTTPS + 应急 DNS | 运维复杂度上升 |
| 故障转移 | 连续 3 次失败切备用，成功后逐步切回 | 切换瞬间流量特征突变 |
| 会话恢复 | 会话 ID 持久化，重启后自动重连 | 需处理重复会话 |
| 时间窗限制 | 仅在业务高峰时段回连 | 运维窗口被压缩 |

保活纪律：**心跳周期必须是分布而不是常数**。同一批植入体如果心跳间隔完全一致，流量侧的周期性特征足以直接聚类。抖动比例建议 20%-40%，并按分组错开相位。

### 第 5 步：权限维持

按平台列清单，每项都要写：实现方式、触发时机、检测点、恢复难度。

**Windows**

| 方式 | 触发 | 检测点 |
|---|---|---|
| 服务（新建或劫持现有服务） | 开机 | 7045、服务二进制路径异常 |
| 计划任务（登录/启动/空闲触发） | 定时或登录 | 4698、任务 XML 内容 |
| 注册表 Run/RunOnce | 登录 | 注册表监控（Sysmon 12/13） |
| WMI 事件订阅 | 系统事件 | `__EventFilter`/`__EventConsumer` 查询 |
| COM 劫持 | 特定程序启动 | CLSID 注册表项变更 |
| DLL 搜索顺序劫持 | 程序启动 | 镜像加载（Sysmon 7）路径异常 |
| 启动目录 | 登录 | 文件创建（Sysmon 11） |

**Linux**

| 方式 | 触发 | 检测点 |
|---|---|---|
| systemd 服务/定时器 | 开机/定时 | unit 文件新增、enable 状态变更 |
| cron / cron.d / anacron | 定时 | crontab 变更、文件写入 |
| SSH 授权密钥 | 登录 | authorized_keys 修改时间与内容 |
| shell 启动文件 | 登录 | .bashrc/.profile 写入 |
| LD_PRELOAD 注入 | 进程启动 | /etc/ld.so.preload 存在性 |
| PAM 模块 | 认证 | pam 配置变更 |
| 内核模块 / eBPF | 加载 | 模块列表、eBPF 程序枚举 |

维持纪律：**每台机器最多保留 2 个维持点，且互相不依赖**（一个被清，另一个仍能恢复）。保留超过 3 个会显著提高被发现概率，且清理时容易遗漏。所有维持点必须在运维台账里登记，否则清场时清不干净。

### 第 6 步：批量会话管理

| 功能 | 设计要点 |
|---|---|
| 分组 | 按网段/域/权限/版本打标签，支持多标签 |
| 任务下发 | 支持定向（单机）、按组、按标签、全量；下发前预估影响面 |
| 并发控制 | 全量任务必须限速（如每分钟不超过 N 台），避免同时产生大量外联 |
| 结果回收 | 分页拉取，大结果分块传输并校验哈希 |
| 版本灰度 | 新版本先发 5% 分组，观察存活率 24 小时后再扩大 |
| 状态同步 | 会话状态带最后心跳时间，超过 3 个周期标记为失联而非删除 |
| 审计 | 每条任务记录：下发人、时间、目标集、命令、返回状态 |

批量运维三禁忌：全量同时执行高噪声命令、对失联会话反复重试（会暴露重试特征）、在业务高峰做全量操作。

### 第 7 步：检测对抗（控制面视角）

| 面 | 手法 | 说明 |
|---|---|---|
| 流量 | 协议伪装为常见应用（HTTP/2、WebSocket、DNS） | 与真实应用流量混叠 |
| 地址 | 域前置、CDN 中转、入口轮换 | 隐藏真实控制端 |
| 时序 | 心跳抖动、任务批量错峰、空闲期静默 | 破坏周期性特征 |
| 载荷 | 内存执行、反射加载、分阶段投递 | 减少落盘痕迹（实现细节归 evasion） |
| 配置 | 每批次独立配置档（URI 路径、UA、头部顺序） | 避免同签名聚类 |
| 行为 | 任务白名单化、限制单机噪声操作 | 减少 EDR 行为触发 |

自评方法：把控制面流量与同环境真实业务流量做特征对比（包长分布、握手特征、心跳间隔方差、连接目标分布）。差异项就是整改项。

### 第 8 步：失效与善后

- 会话失联：先判断是网络问题还是被清除。连续 3 周期无心跳 + 同组其他会话正常 → 大概率被清除。
- 地址被封：立即切换到备用入口，评估是否整批受影响，必要时下发新配置。
- 被溯源风险：检查是否存在跨会话可关联的固定标识（相同 URI、相同证书、相同 User-Agent、相同心跳相位）。
- 清场：按台账逐个移除维持点，移除后确认系统功能正常（不要留下服务残留或启动失败）。

## 验证方式

1. **架构可落地**：按设计文档搭出最小可用链路，能完成"上线 → 心跳 → 下发一条任务 → 回收结果"闭环，全程有日志。
2. **参数有代价说明**：参数表每一行都写明代价（隐蔽性/延迟/运维复杂度），缺代价列的项视为未完成设计。
3. **心跳非周期**：抓取 ≥100 个心跳间隔，计算标准差 ÷ 均值 ≥0.15；等于常数则不合格。
4. **容灾有效**：手动切断主通道，会话在 ≤3 个心跳周期内通过备用通道恢复，且台账状态正确更新。
5. **维持点可清理**：按清单逐项执行清理步骤后，系统重启无异常，且清单里每一项都有对应的"验证已清除"命令。
6. **批量限速生效**：全量任务实际并发不超过设定上限（用日志时间戳统计验证）。
7. **台账完整**：任取一个会话，台账能回答"它在哪台机器、什么权限、有几个维持点、当前版本、最后心跳时间"。
