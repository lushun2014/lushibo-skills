# C2 工程细节：通道 / 心跳 / 维持 / 批量 / 特征

本文件是 `lushibo-botnet` 的技术参考。

## 1. 通信通道选型

| 通道 | 载体 | 抗封锁 | 延迟 | 适用 |
|---|---|---|---|---|
| 原始 TCP | 自定义端口 | 低 | 最低 | 内网、已信任链路 |
| HTTPS | 443 + 真实证书 | 高 | 中 | 通用主力通道 |
| WebSocket | 443 升级 | 高 | 中 | 需要长连接与双向推送 |
| HTTP 轮询 | 80/443 | 中 | 高（受轮询间隔限制） | 只能出站的环境 |
| DNS | TXT/A/AAAA 查询 | 高 | 很高 | 应急通道、极端受限网络 |
| 域前置/CDN | 第三方域名 | 很高 | 中高 | 隐藏真实控制端 |
| 云存储/API | 对象存储、公开 API | 高 | 中 | 借合法服务做死信箱 |

通道设计原则：**主通道追求稳定，备用通道追求可达**。主通道用 HTTPS 长连接，备用用 DNS 或云存储死信箱；两条通道不能共用同一个域名或同一张证书。

死信箱模式（store-and-forward）：植入体只与合法第三方服务交互（读写对象存储、发帖/读帖、邮件草稿），控制端异步读写。优点是流量看起来完全合法，缺点是延迟高、依赖第三方条款。

## 2. 心跳与抖动参数

```
基础间隔 T = 60s
抖动比例 j = 0.3
实际间隔 = T × (1 + U(-j, +j))          # 均匀抖动
相位偏移 = hash(implant_id) mod T        # 按植入体错开相位
退避序列 = min(T × 2^n, 600s) + 抖动     # 连续失败时的退避
```

判断指标（自评用）：

| 指标 | 计算 | 合格线 |
|---|---|---|
| 间隔标准差 ÷ 均值 | 统计 ≥100 个间隔 | ≥0.15 |
| 相位分散度 | 同一时刻同时回连的比例 | <5% |
| 退避覆盖率 | 失败时是否触发退避 | 100% |
| 空闲静默 | 无任务时是否仍有非心跳流量 | 应为 0 |

反模式：固定 60 秒心跳、固定重连次数、所有植入体同一相位、失败后立即无限重试。这四种是最容易被聚类的特征。

## 3. 会话与任务模型

**会话状态字段**：会话 ID（稳定且不可跨会话关联）、植入体版本、首次上线时间、最后心跳、当前权限、系统信息摘要、分组标签、维持点清单、当前通道。

**任务模型**：

```
task_id (uuid)      幂等键，重放不重复执行
target_selector     单机 / 组 / 标签 / 全量
command             指令与参数
ttl                 过期时间，超时不再执行
max_concurrency     并发上限
created_by/at       审计字段
status              pending / dispatched / done / failed / expired
result_ref          结果存储引用（分块 + 哈希）
```

幂等要求：同一 task_id 在同一会话上最多执行一次；结果分块上传需支持断点续传。

## 4. 分平台权限维持实现要点

### 4.1 Windows

| 方式 | 实现要点 | 检测点 | 清理 |
|---|---|---|---|
| 服务 | 创建自启动服务，二进制路径可指向合法宿主进程 | 7045、服务路径异常、启动类型 | `sc delete` + 确认注册表键已删 |
| 计划任务 | 触发器选登录/启动/空闲，隐藏任务名于常见前缀下 | 4698、任务 XML | `schtasks /delete /tn` |
| 注册表 Run | HKCU/HKLM 的 Run/RunOnce | 注册表监控 12/13 | 删除值并确认 |
| WMI 订阅 | 永久事件订阅绑定到启动事件 | `__EventFilter`/`__EventConsumer`/`__FilterToConsumerBinding` 查询 | 删除三个对象 |
| COM 劫持 | 劫持 HKCU 下 CLSID 的 InprocServer32 | CLSID 键变更 | 恢复原值 |
| DLL 搜索顺序 | 在程序目录放同名 DLL | Sysmon 7 镜像加载路径 | 删除文件 |

### 4.2 Linux

| 方式 | 实现要点 | 检测点 | 清理 |
|---|---|---|---|
| systemd unit | 自定义 unit + enable，命名贴近系统服务 | unit 文件新增、enable 符号链接 | disable + 删 unit + daemon-reload |
| cron | /etc/cron.d 或用户 crontab，时间避开整点 | 文件写入、crontab 变更 | 删条目并确认 |
| SSH 密钥 | authorized_keys 追加公钥 | 文件 mtime 与内容 | 删除对应行 |
| shell 启动 | .bashrc/.profile 追加 | 文件 diff | 还原备份 |
| ld.so.preload | 写入预加载路径 | 文件存在性 | 删除文件 |
| PAM | 追加 pam 模块 | /etc/pam.d 变更 | 还原配置 |

清理纪律：清理前先做备份（便于事后核对），清理后必须验证"系统重启无异常"且"原维持点不再触发"。

## 5. 批量任务模板

```
# 定向信息收集（低噪声，建议全量前先做 5% 灰度）
collect:
  - os_version, arch, user, privilege
  - egress: direct|proxy, open_ports
  - interpreters: powershell|python|bash
  - security: av|edr presence
  - time_sync

# 限速全量下发示例
dispatch:
  selector: tag=win-server
  concurrency: 20/min
  jitter: 0.4
  ttl: 3600s
  command: <command>
```

全量任务限速公式：`每分钟并发 = 目标总数 ÷ 期望完成分钟数`，并额外乘 0.5 作为安全系数。同时回连的会话数超过控制端连接上限会导致大面积掉线，看起来像"被封"，实际是自己打崩的。

## 6. 特征自评指标

| 特征面 | 采集 | 正常业务基线 | 异常信号 |
|---|---|---|---|
| 连接目标 | 目标域名/IP 分布 | 分散且与业务相关 | 少数几个域名占绝大多数 |
| 连接时长 | 单连接持续时间 | 与应用一致 | 长期保持长连接且无业务流量 |
| 包长分布 | 分桶统计 | 双峰（请求/响应） | 固定小包为主 |
| 请求节奏 | 间隔序列 | 无规律 | 标准差极小 |
| URI 分布 | 路径与参数 | 多样 | 固定路径 + 随机参数 |
| 证书 | 颁发者与有效期 | 主流 CA、有效期正常 | 自签或超短有效期 |
| User-Agent | 字符串 | 与真实客户端一致 | 罕见或版本不匹配 |
| 上传下载比 | 字节比 | 与业务一致 | 长期 1:1 且无内容 |
